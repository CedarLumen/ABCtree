# ABCtree

任务生成器 A 与双求解器 B/C 的三方对抗训练骨架。纯 PyTorch，单文件。

```
A（上层，无外部输入）── 任务 (x, y*) ──┬──> B ──> ŷ_B ──> L_B
                                        └──> C ──> ŷ_C ──> L_C

r_A = L_C - L_B       A 最大化它 ⇒ 生成「B 已经会、C 还不会」的任务
```

| 组件 | 说明 |
|---|---|
| A | 可学习码本（64×8）+ 噪声 + 共享主干 + 两个 head，无外部输入。输出 `x ∈ R^8`（任务必备参数）与 `y* ∈ R^8`（预期输出） |
| B / C | 逐参数同形状的 MLP（8-64-64-8）。初始化 seed 不同，学习率不同 |

## 两段反向

**段一 · A 断联**：任务 detach 后喂给 B、C，各自按经典监督信号反传、更新自己的参数。A 的参数不在这张图里，自检逐参数断言梯度为空。

**段二 · B、C 冻结**：只对 A 的任务参数 `x` 求 `∂L_B/∂x` 与 `∂L_C/∂x`，合并为 `(∂L_B - ∂L_C)/∂x` 后经 `x` 回传到 A。B、C 的参数不在该图内，一个字节都不动（自检逐位比对参数与梯度缓冲）。

**为什么 `y*` 默认 detach**：若让梯度经 `y*` 回传，A 可以把自己的答案直接设成 B 当前的输出，于是 `L_B` 恒为 0、`L_C` 保持最大，`r_A` 被这个退化解瞬间刷满，A 塌缩成「照抄 B」而不再构造任务。默认只经 `x` 回传；要复现这个退化解用 `--grad-via-label`。

## 用法

```powershell
python abctree.py --mode selfcheck          # 机制自检（17 项，grid / prime / prime-proj / ramp 各自可跑）
python abctree.py --mode train --steps 6000 # 单组训练 + 曲线
python abctree.py --mode plot --out runs/x
python abctree.py --mode compare --seeds 0 1 2   # 实验组 vs A 冻结对照组
python abctree.py --mode probe --ft-steps 3000   # 冻结 A 与 B，只让 C 续训：追不追得上

python trend2.py --task grid --reward ramp --lam1 2 --div-w 1   # 多 seed 趋势摊表
```

吞吐（RTX 5060L，bs=64）：solver 64 宽约 60 步/s，8 宽约 110 步/s。6000 步一组 60~100 s。

## 最终配置（唯一让难度上升的一组）

```powershell
python trend2.py --task grid --reward ramp --lam1 2 --div-w 1 --seeds 0 1 2
```

奖励 `r_A = passB · (1 − λ(t) · passC)`，λ 从 0 线性升到 2。
solver 保持原参数量（64×2 = 5256）。实测 9/9 seed 的 `ev_LB` 上升（0.0020 → 0.0103），
同时 `passB` 守住 0.81、`passC` 从 0.47 压到 0.21。

## 参数总表

| 开关 | 默认 | 作用 |
|---|---|---|
| `--task {grid,prime}` | grid | grid：A 出 8 维任务参数；prime：A 出 a,b,c，c 是 B/C 唯一输入 |
| `--reward {diff,gate,ramp}` | diff | diff=`L_C−L_B`；gate=只在 B 会时计 C 的失败；ramp=门控+递增惩罚 |
| `--lam0 / --lam1` | 0 / 2 | ramp 的 C-通关惩罚权重起止值 |
| `--gate-tau / --gate-temp` | 0.02 / 0.005 | 「通关」判据 `L < tau` 与软化温度 |
| `--div-w / --div-lo / --div-hi` | 0 / 0.15 / 0.55 | 抗塌缩：任务参数逐维 std 的允许区间 |
| `--solver-hidden` | 0（=64） | B/C 宽度，0 表示与 A 同宽 |
| `--solver-layers` | 2 | B/C 隐层数 |
| `--fixed-rule` | off | `y*` 改由固定随机规则从 x 决定，A 只能选 x 的位置 |
| `--n-max / --prime-w / --prime-proj` | 1000 / 1 / off | prime 模式的范围、惩罚权重、硬投影 |
| `--grad-via-label` | off | 让梯度也经 `y*` 回传（复现退化解，见「两段反向」） |

## 自检（17/17 通过）

```
== 1. 形状 / 超参 ==
  [PASS] B、C 逐参数同形状   6 tensors
  [PASS] B、C 初始参数不同   max|Δ|=0.6708
  [PASS] B、C 学习率不同     0.001 vs 0.0002
  [PASS] B 输入维度 = d_x，标签不泄漏
== 2. A 的初始任务分布 ==
  [PASS] 任务参数不塌缩      x_std=0.1102
  [PASS] 预期输出不塌缩      y_std=0.1210
  [PASS] head 未饱和         mean|x|=0.131
== 3. 段一断联 ==
  [PASS] A 全部参数梯度为空（段一未连图）
  [PASS] B 参数已更新 / C 参数已更新
== 4. 段二冻结 ==
  [PASS] B 参数逐位不变 / C 参数逐位不变 / B、C 梯度缓冲未被追加
  [PASS] C 梯度源非零 ‖gC‖>0  0.0032
  [PASS] A 收到梯度
== 5. 梯度反转符号（有限差分，float64）==
  [PASS] ∂(L_B-L_C)/∂x 与差分一致（合并符号）    rel=4.35e-10
  [PASS] ∂(L_B-L_C)/∂θ_A 与差分一致              analytic=-0.00030471 fd=-0.00030471 rel=5.35e-09
== 6. 数值稳定性 ==
  [PASS] 20 步无 NaN/Inf
```

梯度的两层差分校验：`∂(L_B-L_C)/∂x` 用逐维中心差分独立算出，与 autograd 的 `gB-gC` 对上（4.35e-10）；A 的参数梯度再把 `y*` 钉在基点做差分，与 `x.backward(gB-gC)` 对上（5.35e-09）。第二层必须钉住 `y*`，否则差分会把 `y*` 随 θ 一起变化的那部分也算进去，与实现（`y*` detach）不是同一个函数。

## 实测结果

三组实验，全部 `steps=3000`，评估用 512 个固定任务点。

### 1. 实验组 vs 对照组（lr_B=1e-3, lr_C=2e-4, n=3）

| 组别 | ev_L_B | ev_L_C | ev_gap | only-B 比例 |
|---|---|---|---|---|
| A 冻结（随机任务） | 0.0051±0.0013 | 0.0051±0.0014 | −0.0001±0.0001 | 0.0000 |
| A 训练 | 0.0117±0.0076 | 0.0222±0.0149 | **+0.0105±0.0074** | 0.0358±0.0313 |

`Δgap = +0.0106`。**对照组 gap 恰好为 0**：5 倍学习率差在固定任务分布上收敛后不产生任何优势，两边都到 ~0.005。也就是说这个 gap 完全是 A 造出来的，不是 lr 差自带的。

### 2. 等学习率对照（lr_B = lr_C = 1e-3, n=3）

| 组别 | ev_gap | only-B 比例 |
|---|---|---|
| A 冻结 | −0.0000±0.0000 | 0.0000 |
| A 训练 | **+0.0008±0.0005** | 0.0000 |

把 lr 拉平，A 造出的 gap 掉了一个数量级且 only-B 归零。**A 利用的正是学习率差。**

### 3. 探针：冻结 A 和 B，只让 C 在 A 的最终任务分布上续训

| | L_B（冻死） | L_C | gap | only-B |
|---|---|---|---|---|
| 续训前 | 0.0206 | 0.0402 | +0.0196 | 0.078 |
| 375 步 | 0.0206 | 0.0168 | −0.0038 | 0.000 |
| 3000 步 | 0.0206 | 0.0129 | −0.0076 | 0.000 |

**C 在 375 步内追上并反超 B。** 分布一停，"只有 B 能完成"立刻消失。

## 结论：机制生效，但「只有 B 能完成」是瞬态的

A 确实学会了它该学的东西——它在把任务分布往 C 的训练前沿之外推。训练中 `mean|x|` 从 0.13 升到 0.86~0.99（逼近 tanh 边界），这正是 C 覆盖最少的地方。这不是 bug，是奖励设计的必然指向。

但 B、C **同架构同容量**，差别只有初始化和学习率。按构造，这类差异只影响「多快跟上」，不影响「最终能不能」。所以：

- A 造出的是 **前沿课程**（把任务推到对手还没跟上的地方），不是**能力分工**；
- 想让这个 gap 稳住，只能持续加速漂移，此时 gap 是速度差的稳态值，不是能力差；
- 要让优势变成结构性的，必须让 B、C 在**非速度维度**上不同：容量不同、C 的部分参数冻结、或两者预训练于不相交的任务域。当前工程严格按「架构完全相同」实现，没有这些。

配套建议：如果目标是「A 生成只有 B 能解的任务」作为长期性质，`--lr-C` 之外至少还要一个结构性约束，否则探针一定能把 gap 抹平。

## 已证明 / 未证明

**已证明（附实测输出）**
1. 段一 A 完全断联：A 全部参数 `.grad is None`。
2. 段二 B、C 零改动：参数逐位相同，梯度缓冲未追加。
3. 梯度反转符号正确：`∂(L_B-L_C)/∂x` 与中心差分一致 4.35e-10；A 参数梯度一致 5.35e-09。
4. A 无输入仍能产出多变任务，初始 `x_std=0.1102 / y_std=0.1210`，未饱和。
5. A 训练会制造 gap（+0.0105 vs 对照组 −0.0001），等 lr 时消失（+0.0008）。
6. gap 在冻结分布下 375 步内翻转成 −0.0038。
7. 3000 步无 NaN/Inf。

**未证明 / 需注意**
1. `only-B 比例 = 3.6%` 的绝对量级依赖 `success_thr=0.02 / fail_thr=0.06` 两个阈值，换阈值数值会变，趋势不变。
2. n=3 seeds，`ev_gap` 的 std 与均值同量级（0.0074 vs 0.0105），只说明方向稳定，不给点估计。
3. A 向 tanh 饱和区漂移的长期后果（两侧梯度同时消失）未测超过 3000 步的轨迹。
4. `--grad-via-label` 的退化解路径已实现但未跑对照，预期 `L_B→0`、A 塌缩到照抄 B。

# 附：给 A 的输出加质数约束（`--task prime`）

A 改成输出三个数 `a, b, c`：`a, b` 要求为质数、`c` 要求等于 `a·b`，**`c` 是 B、C 的唯一输入**。
惩罚进 A 的奖励：

```
P = (|a - 最近质数| + |b - 最近质数|) / n_max  +  |c - a·b| / n_max²
loss_A = (L_B - L_C) + prime_w · mean(P)
```

`n_max=1000`（a,b ∈ [2,1000]，共 168 个质数），`c ∈ [2, 10⁶]`。送给 B、C 的是 `c / n_max²`
（同一信息的线性缩放；`c` 本身到 1e6，直接进 64 宽 MLP 会让首层 tanh 全饱和、梯度精确为 0，实测过）。

## 预登记判据

「题越来越难」= 前 1/6 评估段的 `ev_LB` 均值 < 后 1/6（B 在 A 的题上越来越差），或 `ev_c_med` /
`ev_c_log_width` 单调抬高。反向即「越来越简单」。

## 实测（3 seeds × 6000 步，两种变体）

### 软惩罚（Cedar 原样要求）

| seed | ev_LB 前 | ev_LB 后 | c 中位 前 | c 中位 后 | 约束满足率（后段） |
|---|---|---|---|---|---|
| 0 | 0.0078 | 0.0029 | 288 907 | 118 556 | 2.2% |
| 1 | 0.0071 | 0.0008 | 252 015 | 10 955 | 8.8% |
| 2 | 0.0084 | 0.0018 | 274 412 | 267 242 | 32.6% |
| 均值 | **0.0078±0.0006** | **0.0018±0.0008** | 271 778 | 132 251 | 14.5±13.1% |

**3/3 seed 的 ev_LB 下降（4.3 倍），c 中位数 3/3 下降。题越来越简单，而且从来没真正满足过约束。**

### 硬投影（`--prime-proj`，a,b 直接取最近质数 + STE 保梯度）

| seed | ev_LB 前 | ev_LB 后 | c 中位 后 | log10(c) 宽度 | 约束满足率 |
|---|---|---|---|---|---|
| 0 | 0.0055 | **0.0000** | 994 009 | 0.00 | 100% |
| 1 | 0.0049 | 0.0165 | 743 592 | 4.32 | 100% |
| 2 | 0.0073 | 0.0110 | 790 820 | 4.49 | 100% |
| 均值 | 0.0059±0.0010 | 0.0092±0.0069 | 842 807 | 2.93±2.08 | 100% |

**双峰**：seed 0 塌缩成一道固定题（`a=b=997`、`c=994009`、`c_bins=1`、`L_B=0.000`）；
seed 1、2 的 `L_B` 反而升了 2～3 倍、`c` 的对数跨度撑到 4.3～4.5 个数量级。
均值差 +0.0033 < seed 间 sd 0.0069 ⇒ **UNRESOLVED，不可判**。

## 结论：不会变难。三个机制层原因

1. **质数是零测集，V 形惩罚推不上去。** 到最近质数的距离是锯齿函数，梯度恒为 ±1（归一化后
   1/n_max），SGD 只能把 a 逼近到 O(lr) 的邻域。实测 `ga` 从头到尾稳在 **1.7～2.5**（相对
   `n_max` 是 0.2%），满足率在 2%～33% 之间跳，**从不接近 100%**。更关键的是：一旦落在质数上，
   沿格点方向没有任何驱动力 —— 所以「a 必须是质数」这条惩罚既推不满、也不含「往大处走」的分量。
2. **奖励方向相反。** `r_A = L_C - L_B` 要的是「B 做得好」，与「题变难」直接对立。任何变难都
   只能来自别的项的副作用，不能来自这个奖励本身。
3. **输入维度从 8 塌到 1。** grid 模式 `x ∈ R^8`；prime 模式 B、C 只收到标量 c。标量→8 维回归
   对 64×64 MLP 太容易，`ev_LB` 从 grid 的 0.01～0.02 掉到 0.002。

## 要让它真的越来越难，得改的是哪一处

| 目标 | 要加的东西 | 备注 |
|---|---|---|
| 数字越来越大 | 幅度项 `relu(min_c(t) - c)/n_max²`，`min_c` 随步数抬升 | 唯一直接的「变大」驱动力，10 行 |
| 对 B 越来越难 | 把奖励从 `L_C - L_B` 换成难度带 `exp(-((L_B - L*)²/σ²))`（最近发展区） | B 变强后 A 必须换更难的题才能留在带内；这是把「变难」变成性质而不是碰运气 |
| a,b 真是质数 | 硬投影 + STE（已实现，`--prime-proj`） | 软惩罚做不到，见上 |

## 三个实现坑（都已修，留在代码里当注释）

1. `c` 直接进 B、C 会让首层 tanh 全饱和、`‖gC‖` 精确为 0 ⇒ 必须缩放。
2. 硬投影 `c = p_a · p_b` 会整条切断 A 的梯度（质数表是常量，查表结果 `requires_grad=False`，
   报 `One of the differentiated Tensors does not require grad`）⇒ 必须用 STE。
3. STE 的解析梯度与有限差分**必然不一致**（这就是直通估计器的定义），自检里不能比 FD，
   改成验「前向取质数、反向恒等」。

## 追问：C 的成功率越来越高，不该推动题变难吗？

这个链条在机制上成立，但它要求 A **不能走「把题变简单」这条退路**。四组对照（各 3 seeds × 6000 步）：

| 促难压力 | ev_LB 前段 | ev_LB 后段 | ev_gap 前→后 | c_bins 前→后 | 结论 |
|---|---|---|---|---|---|
| 基线（lr_C=2e-4） | 0.0078±0.0006 | 0.0018±0.0008 | 0.007→0.001 | 2.5→4.3 | 变简单 |
| 等学习率（消掉速度差） | 0.0093±0.0004 | 0.0015±0.0002 | **0.0000→0.0000** | 2.4→3.1 | 变简单 |
| 门控奖励 `r_A = L_C·1[L_B<τ]` | 0.0088±0.0005 | 0.0009±0.0004 | 0.0009→0.0000 | 2.1→2.7 | 变简单（更快） |
| lr_A ×10（0.01） | 0.0106±0.0019 | 0.0008±0.0008 | **0.0103→0.0000** | 9.6→1.5 | 变简单且塌缩 |

**12/12 次运行都变简单。** 三条机制解释：

**1. 因果方向是反的。** C 的成功率确实在升（`ev_LC` 与 `ev_LB` 同步下降），但它是**「A 把题变简单」的结果**，
不是驱动 A 变难的原因。拿它当输入去推 A，等于把下游读成上游。

**2. 差值奖励自带退路。** `L_C - L_B` 里让 B 更成功比让 C 更失败更近、更快、更局部。

**3. 学习者的吸收速度 > A 制造难度的速度。** A 每步只把任务参数动一点，而 B、C 在**同一批题上**
每步都拿到直接监督（MSE 回归）。二阶对抗信号打不过一阶监督信号 —— 除非任务跨极大动态范围：
硬投影模式下 seed 1/2 把 c 撑到 4.3 个数量级，`ev_LB` 才第一次升到 0.0165。

**lr_A ×10 那组最刺眼**：如果瓶颈只是「A 太慢」，放大 10 倍该看到变难；实际看到的是**更快更彻底的塌缩**
（`c_bins` 9.6→1.5，约束满足率 →96.7%，早期 gap 0.0103 然后归零）。

**门控版（按你的逻辑实现）也没救回来**：`gate≈1` 时它退化成「最大化 L_C」，而 A 仍然可以用
「收窄任务分布、让 B 几乎全会、C 稍微差一点」拿到这份分。

⇒ **缺的是抗塌缩项**，`A` 的任务分布离散度（熵/对数跨度）在这套奖励里没有任何一项在守。
这是唯一能让你的链条真正启动的东西。

## 抗塌缩项 + 容量：难度到底卡在哪

三组对照（grid 模式，各 3 seeds × 6000 步）：

| 配置 | ev_LB 前→后 | ev_gap 前→后 | x_std 前→后 | mean\|x\| 后段 | only-B |
|---|---|---|---|---|---|
| 基线（div=0, solver 64） | 0.0077→0.0034 | 0.0114→0.0039 | 0.545→0.006 | 0.995 | 1.7% |
| + 抗塌缩（div=1, solver 64） | 0.0024→0.0024 | 0.0056→0.0042 | 0.354→0.342 | 0.43 | 0.07% |
| + 抗塌缩 + solver 宽度 8 | 0.0070→**0.0010** | 0.0549→**0.0203** | 0.374→0.275 | 0.27 | **3.7%** |

**抗塌缩是成功的**：x_std 稳在 0.34（基线崩到 0.006）、不再滑进 tanh 饱和区（0.995→0.43）、gap 从「掉到 1/3」变成「基本持平」。

**容量缩小把 gap 放大了 5～10 倍**：solver 从 5 256 参数降到 216 参数，gap 从 0.0056/0.0042 变成 0.0549/0.0203，only-B 从 0.07% 升到 3.7%。这是「只有 B 能完成」第一次有了实质量级。

**但 ev_LB 依然单调下降，0/3 seed 上升。** 原因在 `x_std` 那一列：solver 变小之后，A 把任务分布**进一步收窄**（0.374→0.275，`mean|x|` 0.55→0.27），主动把题压进 B 的能力圈。

⇒ **缩小 B 不会让题变难，只会让 A 把题的分布再收窄一圈。** `L_C - L_B` 里的 `-L_B` 是一个比「让 C 失败」更省力的旋钮，它在任何容量下都存在。这就是「越来越难」在这套奖励下不可达的根因。

下一步唯一还没试的：把 τ 做成**贴着 B 当前水平自适应**（例如 τ = 当前 batch 的 L_B 中位数），让门控真正卡住 —— 现在的 τ=0.02 在 L_B≈0.009 时门一直开着（gate≈0.85），等于没门。

## ramp 奖励：优先级门控 + 递增惩罚（唯一让难度上升的配置）

`r_A = passB · (1 − λ(t) · passC)`，`passX = sigmoid((τ − L_X)/temp)`，`λ(t)` 从 `lam0` 线性升到 `lam1`。
乘性写法把「优先保证 B 通关」变成结构约束：B 不通关时 `r_A≈0`，C 多失败都拿不到分。

原参数量（solver 64×2 = 5256），grid 模式，3 seeds × 6000 步：

| 配置 | ev_LB 前 | ev_LB 后 | Δ | passB 后 | passC 后 | only-B 后 | seed 上升 |
|---|---|---|---|---|---|---|---|
| ramp λ1=2, div=0 | 0.0033±0.0008 | 0.0097±0.0042 | **+0.0064** | 0.831 | 0.466 | 5~10% | **3/3** |
| ramp λ1=2, div=1 | 0.0020±0.0005 | 0.0103±0.0011 | **+0.0083** | 0.811 | 0.215 | 20~46% | **3/3** |
| ramp λ1=5, div=1 | 0.0043±0.0001 | 0.0127±0.0019 | **+0.0085** | 0.770 | 0.423 | 2~33% | **3/3** |

**9/9 个 seed 的 ev_LB 都在上升**，这是整条线里第一次出现「题越来越难」。之前所有配置（diff / gate / 缩容量 21~5256 参数）都是 0/15 上升。

诚实标注两点：
1. **λ 从 2 加到 5 几乎没差别**（0.0103→0.0127，Δ 只从 0.0083 到 0.0085），所以不是干净的剂量反应，只能说方向稳定。
2. **三组末期 `mean|x|` 都在 0.90~0.98**，说明 A 主要靠把任务推到 tanh 边角来制造难度，与「饱和伪影」尚未完全分开。判据：评估时按 `|x|` 分箱报 `L_B`，看上升是否只发生在高 `|x|` 箱里 —— 这一步还没做。
